ChronitonDB news
================

This file carries the upgrade notes of each ChronitonDB release, and what a user or an
operator needs to know about a change. Apache Cassandra's own notes stay in NEWS.txt.

Not yet released on chronitondb-sandbox
---------------------------------------

New features
------------
 - The virtual table system_views.jvm_memory_pools shows the memory pools of the JVM of
   the node that answers the read: the name and the type of each pool, and its used,
   committed and maximum size in bytes. It is read only and has no setting. See
   docs/reference/virtual-tables/jvm-memory-pools.md.

Upgrading
---------
 - During a rolling upgrade, a node that does not have the table yet refuses a read of it
   with "table jvm_memory_pools does not exist".

Moving back
-----------
 - Before the last node that has system_views.jvm_memory_pools moves back to a release
   without it, list the grants on the table as a superuser, on a node that has it, with
   LIST ALL PERMISSIONS ON system_views.jvm_memory_pools NORECURSIVE, and for each role
   listed run REVOKE ALL PERMISSIONS ON system_views.jvm_memory_pools FROM <role>.
   A node without the table refuses both statements. What a grant left behind does is on
   the reference page of the table.
